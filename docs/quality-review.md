# 质量审查与验收记录 · 2026-09-22

## 结论边界

本项目是可实际操作、持久化保存的课程系统，不是获得企业签字验收的生产系统。不能声称“完美无瑕”“所有路径零缺陷”或“严格符合某家企业全部需求”。本轮不更换云数据库，不改动现有业务数据，不放开旧入口。

## 本轮修正

| 范围 | 修正及依据 |
|---|---|
| 数量 | 拒绝布尔、数组、对象、指数文本及小于克的精度，避免隐式转换或舍入 |
| 质量门控 | 已报废批次禁止通过重新检验改变质量状态；隔离/报废组批禁止继续投料 |
| 状态转换 | 停用场地不能建批；已结束需求不能再取消；投放日期不能早于签收 |
| 唯一标识 | 新业务记录使用完整 UUID，保留旧编号兼容 |
| 请求边界 | JSON 和附件按实际读取字节限制大小，不仅依赖 Content-Length；非法 JSON 返回可理解错误 |
| 登录 | 原子累计失败次数，并发第 13 次起限流；成功登录清理过期会话并撤销当前旧令牌 |
| 账号 | 角色限定自有枚举，阻止原型属性被当成角色；并发幂等账号操作返回同一结果 |
| 客户端 | 初始加载错误可见、登录超时可恢复；退出请求失败不伪装退出成功 |
| 保存反馈 | 区分提交成功和刷新失败，避免诱导重复业务提交及重复上传/导入 |
| 导出 | 与列表复用筛选排序；防范前导空白后的 CSV 公式注入 |
| 导入 | 本地预检重量精度、真实日期、五列结构与桶数上限；超大文件不会保留旧预检结果 |
| 日期 | 业务日、熟化日期和日报统一 UTC+08；事件时间戳仍保存 UTC |
| UI | 海洋主题的共享颜色、背景、对比度、状态字号、键盘焦点、移动端表单及减弱动画 |

## 验证范围

- 原有领域测试 16 项、异常流程 16 项、关系库 8 项及网关边界测试通过。
- 新增质量回归 14 组：输入、状态、司机隔离、ID、读取限额、CSV、跨午夜日期。
- 新增安全 API 回归 7 组：非法载荷、体积、角色枚举、并发限流、账号命令幂等、会话轮换/退出。
- 本地真实 D1/R2 API 测试通过：登录、权限、并发库存预留、幂等、完整退回复检再投放及结项、禁用账号、附件上传下载、导入整批回滚、备份不泄露认证材料。
- TypeScript 静态检查通过。采用 React 检查清单复核异步错误处理、列表派生数据、操作状态和可访问标签。
- 13 个业务页面在桌面与 390 × 844 手机视口均能渲染，无页面级横向溢出；宽表格允许容器内横向滚动。手机新建表单目视检查通过。
- 测试写入仅发生在本地模拟数据库；不把测试生成的账号、附件、流水上传到生产。

## 依赖安全检查

2026-09-22 的 npm 公告库扫描从 19 项（9 高危、9 中危、1 低危）降至 0 项。升级 React/React DOM/RSC 至 19.2.8，Vinext 至 beta.10、Vite 至 8.3.0、Cloudflare 工具链至匹配版本，并更新间接依赖。为 Drizzle 的旧编译器子依赖定向覆盖 esbuild 0.28.1，未采用破坏性降级建议；覆盖后的 TypeScript 转译和 Drizzle 迁移元数据检查通过。

“0 告警”仅指扫描时公告库已知依赖问题，不代表代码无漏洞或完成渗透测试。Vinext 仍为预发布版本；构建有未来 Vite 配置兼容性提示，不影响本次构建，但企业选型需评估稳定性。

## 尚不能代替的企业验收

1. 业务负责人签字确认：熟化期限及检测标准、退回料处理、运输损耗、审批分离、人员可见范围。现有规则是明确的教学假设，不是法规合规结论。
2. 运维验收：生产账号初始化与密码重置制度、MFA/企业 SSO、告警、日志保留、故障演练、完整 D1/R2/认证数据备份恢复及 RPO/RTO。
3. 规模验收：当前全局业务版本及快照适合课程规模，未做企业峰值负载、长时间浸泡、地域容灾或独立渗透测试。
4. 用户验收：桌面/手机检查不是全部设备与辅助技术兼容认证；需让实际餐厅、司机、质量员和项目负责人逐项试用。
5. 数据与隐私：只使用模拟资料；真实个人信息、合同或检测报告上线前需确定收集范围、访问权限和保留期限。

这些条件没有完成前，不建议用本系统直接承载真实生产或敏感数据。
